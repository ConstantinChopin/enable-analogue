# Demo choreography — one continuous morning

**Principle:** the demo is a single narrative ("Tuesday morning at the Paris desk"), not a feature tour. Journeys A/B/C are threads the story pulls through. Deck and demo interleave: decision board → live thread → decision board → live thread.

**Skipped on purpose:** sign-in, onboarding. The demo opens inside a desk with months of history. Onboarding is narrated only if asked.

## Beats (~20–25 min inside the 45-min deep dive)

## Build requirements this creates

1. **Presenter keys:** invisible — nothing renders unless invoked. Checkpoints as built: **1** morning · **2** commission · **3** record · **4** ask · **5** refusal · **6** v1 rewind · **7** traveller · **8** admin confirm · **0** reset. Plus **N** narration overlay and **V** build vintage. One keystroke recovers any stumble.
2. **Seeded deterministic data:** answer traces are authored; no live model calls; nothing can hang or hallucinate. If asked: "it's a design prototype — the intelligence is scripted; the design is the deliverable."
3. **v1/v2 world toggle** for the advisory iteration beat.
4. **Role change is a sign-out and sign-in**, not a toggle (layout-exploration §9) — the sign-in screen carries the four demo accounts. The dock's tile set changes with the role, and routes are scoped, so typing an admin URL as an advisor returns you to your own briefing. That *is* the isolation proof.
5. **Reset to opening state.**
6. Recorded backup video of the full run.

## Honesty lines for the demo

- The prototype is a reconstruction with an analogue dataset; the quotes on the boards are verbatim from the engagement's calls.
- The v1 world is a rebuild of the design that was reversed on 2026-03-31 — shown so the failure can be seen, not just claimed.
- Scripted intelligence, declared if probed.
